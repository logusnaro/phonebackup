# 현재 알려진 이슈와 운영 전제

## 이번 안정성 수정에서 해결한 항목

- Windows 앱 중복 실행 시 포트 충돌로 두 번째 프로세스가 종료되던 문제를 단일 실행 잠금으로 방지했습니다.
- WPF 시작·화면 초기화·백그라운드 작업의 예외를 `%TEMP%\PhoneBackup-crash.log`에 남깁니다.
- Android 네트워크 감시를 UI 스레드에서 분리하고 Wi‑Fi(`UNMETERED`)에서만 백업하도록 했습니다.
- Android 폴더 권한 저장 실패를 처리하고, 구형 Android에서 사용할 수 없는 `java.time` 의존성을 제거했습니다.
- Android 일시적 네트워크 실패는 최대 8회 재시도 후 PC에 실패 상태를 회신합니다.
- PC 요청 백업은 Android가 완료·실패 결과를 PC에 회신합니다.
- 백업 폴더 설정을 DB에 저장하고, 같은 상대 경로의 변경 파일은 SHA-256 버전 폴더로 분리합니다.
- PC 예약 설정이 실제 백업 요청을 생성하도록 실행기를 연결했습니다. PC가 꺼진 회차는 생성되지 않습니다.
- Android 백업 Worker를 foreground worker로 승격해 장시간 전송 중 화면 종료·프로세스 회수 위험을 줄였습니다. 알림 영역에서 백업 상태를 확인할 수 있습니다.
- 파일 업로드를 8MB chunk 단위로 전송하고 PC가 받은 offset을 반환하도록 해 Wi‑Fi 단절 후 같은 파일을 중간 위치에서 재개할 수 있습니다.

## 아직 정식 업무 운영 전에 해결해야 할 항목

- Android에서 사용자가 설정 화면의 ‘강제 종료’를 직접 실행한 경우에는 Android 정책상 네트워크 폴링을 재개할 수 없습니다. 사용자가 앱을 한 번 실행하거나 기기를 재부팅하면 WorkManager가 다시 예약됩니다.
- chunk 임시 파일은 PC의 시스템 임시 폴더에 남을 수 있으므로, 장기간 중단된 임시 파일 정리 작업이 추가로 필요합니다.
- Android 10 이상은 SAF로 사용자가 폴더를 선택해야 합니다. 자동 검색은 구형 Android에서만 제한적으로 사용합니다.
- 주소록 중복 병합·필드별 충돌 선택·승인함·VCF 안전 백업 화면은 아직 완성되지 않았습니다.
- PC에서 휴대폰으로 파일 복구 UI와 복구 충돌 선택은 아직 완성되지 않았습니다.
- Release 서명 APK, Windows 설치 관리자, 2차 백업, 저장공간 사전 검사와 실기기 자동화 테스트가 필요합니다.

## 검증 기준

정식 배포 전 다음을 두 대의 실제 삼성폰에서 확인해야 합니다.

1. 백업 중 앱 화면 종료, 최근 앱 제거, 강제 종료, 재부팅
2. Wi‑Fi 단절·IP 변경·PC 재시작·저장공간 부족
3. 1GB 이상 파일과 같은 경로에서 내용이 바뀐 파일
4. 두 폰 동시 백업과 예약 회차 건너뛰기
5. 주소록 중복·삭제·앱 전용 계정 배포
6. 토큰 폐기·인증서 변경·사설망 외 접근 차단

업무 원본 삭제는 위 검증과 PC 외부 2차 백업이 확인되기 전까지 실행하지 않습니다.
